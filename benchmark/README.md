# Benchmark

Тестовый набор для оценки поиска BM25 и отказов. Решения и результаты —
[spec/tech/rag.md](../spec/tech/rag.md).

## Запуск

```bash
python -m benchmark.run                 # текущая конфигурация приложения
python -m benchmark.run --save          # + отчёт в benchmark/results/
python -m benchmark.run --grid --save   # сравнение: нормализация, расширение, k1 и b
python -m benchmark.run --mode stem --k1 1.5 --b 0.5 --no-expand --title-weight 1 --min-score 8
```

**В рантайме (на сдаче):** `python -m app` → `http://127.0.0.1:8000/admin` → войти
по токену из консоли → раздел «Benchmark поиска» → «Запустить benchmark». Можно
поменять параметры и сразу увидеть метрики, разбор ошибок, ловушки и выдачу по
каждому вопросу. Это тот же код, что и CLI.

## Формат `queries.jsonl`

Одна строка — один запрос:

```json
{"id": "q17", "type": "regular", "query": "работодатель говорит, что первый месяц стажировка и платить не будет",
 "topic": "испытательный срок", "style": "бытовой", "split": "train",
 "relevant": ["tk_70", "tk_132", "tk_136", "tk_21"],
 "reference": "Нельзя: на испытании действуют все нормы трудового права…"}
```

- `type` — `regular` (ответ есть в корпусе) или `trap` (ответа нет, ожидается отказ).
- `relevant` — не меньше трёх меток для обычного вопроса. Метка — `doc_id` или
  статья целиком: `tk_81` засчитывает фрагменты `tk_81_1`, `tk_81_2`.
- `reference` — эталонный ответ (для ручной проверки Accuracy после подключения LLM).
- `style` — `юридический` или `бытовой`: метрики считаем отдельно (разрыв словаря).
- `split` — `train` (нечётные номера: по ним составлен словарь расширения и
  подобраны параметры) или `control` (чётные: проверка без подгонки).

## Состав

| Тема | Обычных |
| --- | --- |
| Оформление и трудовой договор | 5 |
| Рабочее время, совмещение с учёбой | 5 |
| Оплата труда, задержки | 5 |
| Испытательный срок | 3 |
| Отпуска, учебные отпуска | 4 |
| Увольнение | 4 |
| Договор подряда и услуг (ГПХ) | 4 |
| Самозанятость | 4 |
| **Итого** | **34** + 6 ловушек |

## Метрики

Recall@5, Recall@10, MRR@10 — по обычным вопросам; Correct Rejection Rate — по
ловушкам; False Rejection Rate — доля обычных вопросов с ошибочным отказом;
Accuracy — ручная проверка ответов LLM по `reference` (пока ответ — заглушка).
