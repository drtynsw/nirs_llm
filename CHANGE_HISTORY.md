Тесты: 80, все проходят. Поиск не изменился (Recall@5 0,412, Recall@10 0,540,

При отказе модели в журнал и отчёт попадает HTTP-код или фиксированное сообщение о сети. Тело ошибки провайдера не сохраняется.

### КТ2 — проверка источников ответа

Проверка ссылок и авто-Accuracy учитывают закон и фактический контекст модели. Формат списка неподтверждённых номеров сохранён.

### КТ2 — один benchmark за раз

Параллельный HTTP-прогон получает 409. Блокировка охватывает вычисление и сохранение отчёта, в том числе при ошибке.

### КТ2 — граница HTTP-запроса

Оба POST проверяют лимит 16 КиБ перед чтением тела. Административный POST сначала проверяет токен.

## КТ2 — BM25 и benchmark (ноябрь 2026)

- Собственный индекс BM25 (`app/retrieval/`): токенизация, стоп-слова,
  лемматизация pymorphy3 или свой стеммер Snowball, инвертированный индекс,
  вес названия статьи, словарь расширения запроса. Заглушка поиска удалена.
- Порог «нет ответа» (С4) по оценке лучшего документа; общий конвейер `app/rag.py`
  для сервера и benchmark. Индекс строится при старте сервера.
- Benchmark: 34 размеченных вопроса (3–5 релевантных статей и эталонный ответ) +
  6 ловушек; Recall@5/10, MRR@10, Correct/False Rejection Rate, разбор ошибок,
  сравнение конфигураций (`python -m benchmark.run --grid`).
- Запуск benchmark в рантайме со страницы `/admin` (`POST /api/admin/benchmark`).
- Итог: Recall@5 0,41, Recall@10 0,54, MRR@10 0,77, CRR 0,67, ложных отказов 3%.
- Тесты: 28 → 51 (BM25 сверен с примером из занятия 3).
- LLM (`app/llm.py`): OpenAI-совместимый API на стандартной библиотеке, провайдер
  в `.env` (примеры — `.env.example`); промпт по найденным статьям, отказ
  `НЕТ_ОТВЕТА` → С4, проверка ссылок на статьи вне выдачи, учёт возраста < 18,
  при ошибке модели — заглушка с меткой «модель недоступна» (`mode = "fallback"`).
- Benchmark с ответами модели (`--llm`, галочка на `/admin`): Accuracy (авто),
  отказы LLM на ловушках, доля ссылок вне выдачи. Тесты: 51 → 68 (имитатор API).
- Прогон на реальной модели (deepseek-v4.1-flash через ProxyAPI): Accuracy ручная
  0,765 (26/34), CRR 1,00, ложных отказов 9%; ручная проверка —
  `benchmark/results/2026-11-18_manual_accuracy.md`.
- По итогам прогона: `max_tokens` 1500, повтор при сбоях и пустом ответе,
  температура 0, частичный ответ вместо отказа, очистка Markdown, обрезка
  незаконченного предложения; тесты не обращаются к модели из `.env`. Тесты: 68 → 73.
