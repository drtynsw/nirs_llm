# API

Все ответы — JSON в UTF-8. Ошибки: `{"error": "текст"}` с кодом 4xx.

Оба POST принимают JSON до 16 КиБ. Сервер проверяет длину до чтения тела.
Превышение лимита возвращает 413, неверная или неоднозначная длина и неподдерживаемое
кодирование передачи — 400. Административный маршрут сначала проверяет авторизацию.

## POST /api/ask

Запрос:

```json
{"question": "Сколько длится испытательный срок?", "top_k": 5, "age": 17}
```

| Поле | Тип | Правило |
| --- | --- | --- |
| question | строка | обязательно, 1–500 символов после обрезки пробелов |
| top_k | целое | необязательно, по умолчанию 5, приводится к 1–10 |
| age | целое или null | необязательно (с КТ2); если задано — 10–100, иначе 400 |

Ответ 200:

```json
{
  "question": "Сколько длится испытательный срок?",
  "answer": "…",
  "mode": "prototype",
  "documents": [
    {"doc_id": "tk_70", "citation": "ст. 70 ТК РФ", "law": "ТК РФ",
     "article": "70", "title": "Испытание при приеме на работу",
     "score": 11.0, "snippet": "…"}
  ],
  "age_group": "16–17",
  "age_documents": [
    {"doc_id": "tk_268", "citation": "ст. 268 ТК РФ", "law": "ТК РФ",
     "article": "268", "title": "Запрещение направления в служебные командировки…",
     "snippet": "…"}
  ],
  "took_ms": 12.4
}
```

- `documents` отсортированы по убыванию `score`, длина ≤ `top_k`, может быть пустым.
- `answer` всегда заканчивается оговоркой «…не юридическая консультация» (кроме случая С4).
- `mode`: `"rag"` — ответ сформировала LLM; `"prototype"` — LLM не настроена
  (нет `LLM_BASE_URL`/`LLM_MODEL`), ответ формирует заглушка; `"fallback"` — LLM
  настроена, но вернула ошибку, ответ формирует заглушка. Поиск во всех режимах — BM25.
- `unsupported_citations` (с КТ2): номера ссылок, для которых в переданном модели контексте нет однозначного совпадения закона и статьи; обычно `[]`.
- Если оценка лучшей статьи ниже порога (С4), `documents` пуст, а `answer` —
  «В загруженных законах не нашлось подходящих статей…».
- `age_group` (с КТ2): `"до 14"`, `"14–15"`, `"16–17"`, `"18–23"`, `"24+"` или `null`, если возраст не передан.
- `age_documents` (с КТ2): для `age` < 18 — 1–3 статьи о труде несовершеннолетних,
  подобранные по теме вопроса, без повторов из `documents` и без поля `score`;
  иначе `[]`. В `documents` не подмешиваются — ранжирование поиска не меняется.
- Для `age` < 18 в `answer` перед оговоркой добавляется пояснение со ссылками на
  ст. 63, 92, 94, 266–269 ТК РФ.
- Новые поля только добавлены: клиенты КТ1 продолжают работать.

Ошибки 400: пустой вопрос, длинный вопрос, нечисловой `top_k`, некорректный JSON,
`age` не целое число или вне 10–100.

Каждый успешный запрос записывается в аналитику без текста вопроса (`spec/tech/admin.md`).

## Администрирование (с КТ2)

Все запросы — с заголовком `Authorization: Bearer <ADMIN_TOKEN>`.
Без него или с неверным токеном — 401 `{"error": "Нужен токен администратора"}`.
Ответы с `Cache-Control: no-store`.

### GET /api/admin/stats?days=30

`days` — целое 1–365, по умолчанию 30, иначе 400.

```json
{
  "period_days": 30, "since": "2026-10-20",
  "total": 120, "no_answer": 6, "no_answer_share": 0.05,
  "avg_took_ms": 14.2, "age_given_share": 0.6,
  "by_day": [{"date": "2026-11-18", "count": 9}],
  "by_age_group": [{"group": "16–17", "count": 20}, {"group": "не указан", "count": 48}],
  "by_topic": [{"topic": "Увольнение", "count": 31}],
  "age_topic": [{"group": "16–17", "topic": "Рабочее время", "count": 7}],
  "top_articles": [{"doc_id": "tk_80", "citation": "ст. 80 ТК РФ", "count": 25}]
}
```

`by_day` содержит все дни периода, включая нулевые. `by_age_group` — в порядке групп,
`"не указан"` последней.

### GET /api/admin/export.csv?days=30

CSV (UTF-8 с BOM, разделитель `;`) — по строке на запрос:
`ts;age_group;topic;top_k;n_docs;top_docs;took_ms;no_answer`.

### GET /api/admin/benchmark

Параметры по умолчанию и состав набора:
`{"default": {...Config}, "lemma_available": true, "modes": ["none","stem","lemma"], "queries": {"regular": 34, "traps": 6}}`.

### POST /api/admin/benchmark

Прогон benchmark в рантайме (`spec/tech/rag.md`). Тело — все поля необязательны:

| Поле | Тип | Правило |
| --- | --- | --- |
| mode | строка | `none` / `stem` / `lemma` |
| k1 | число | 0,1–5 |
| b | число | 0–1 |
| title_weight | целое | 1–5 |
| min_score | число | 0–100, порог отказа |
| expand | bool | расширение запроса |
| save | bool | сохранить отчёт в `benchmark/results/` |
| llm | bool | получать ответы LLM (медленнее: один вызов модели на вопрос) |

На процесс сервера допускается один HTTP-прогон benchmark (с моделью или без).
Пока он идёт или сохраняет результат, второй корректный POST получает 409 и JSON
с полем `error`. После завершения или ошибки следующий запуск доступен сразу.
Обычные вопросы и GET не захватывают эту блокировку.

Ответ 200 — отчёт `benchmark.run.evaluate`: `config`, `metrics` (`recall@5`,
`recall@10`, `mrr@10`, `correct_rejection_rate`, `false_rejection_rate`, `accuracy`),
`retrieval` (срезы по стилю, части, теме), `errors`, `regular`, `traps`, `took_ms`,
при `save` — `saved` (путь). Неверное поле — 400 «Некорректный параметр: <поле>».
